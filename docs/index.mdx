Keysy uses a **monorepo**: the web app, CLI, service directories, API contracts,
and infrastructure files live in a single Git repository.

## Repository structure

| Directory | Purpose |
| --- | --- |
| `web/` | React and TypeScript web app, built with Vite. |
| `cli/` | Go CLI scaffold, built with Cobra. |
| `api/` | Reserved for the application API service. |
| `auth/` | Reserved for the authentication service. |
| `notify/` | Reserved for the notification service. |
| `contracts/openapi/` | Shared OpenAPI definitions for the API and authentication services. |
| `docs/` | Mintlify documentation and site configuration. |
| `deploy/` | Deployment scaffolding. |
| `otel/` | OpenTelemetry Collector Docker image definition. |
| `supabase/` | Reserved for Supabase configuration. |

<Note>
  Keysy is in its initial scaffolding stage. The web app and CLI still contain
  starter code, the service directories are placeholders, and the OpenAPI files
  do not define endpoints yet.
</Note>

## Working in the monorepo

Work in the directory for the component you are changing. Keep shared API
definitions in `contracts/openapi/` so service and client changes can be reviewed
together.

Create branches from the latest `origin/main` and submit changes through pull
requests. Use `<type>(<scope>): <description>` for commit messages and PR titles,
then squash-merge after review.
