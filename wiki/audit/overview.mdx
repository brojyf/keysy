`audit/` is reserved for the audit service. It currently contains only a
placeholder; there is no service implementation or startup command yet.

## Planned integration

`audit` consumes events from Kafka and inserts them into the audit database.
See [System design](/system-design).

Each outbox row gets its `event_id` when api writes it. If the Outbox Relay
publishes a row again, for example because api stopped before it deleted
the row, the event keeps the same `event_id`. The audit table has a
unique constraint on `event_id`, and `audit` inserts with
`ON CONFLICT DO NOTHING`, so a republished event adds no second record.
`audit` commits its Kafka offset only after the insert succeeds or finds the
`event_id` already stored, so a crash before the insert leaves the event to be
consumed again.

This integration is not implemented yet.
